# FinQuery review, demo instance at 127.0.0.1:8000 (OpenRouter)

Reviewed 2026-09-04 against `.scratch/finquery/spec.md` and tickets 01, 02, 03, 04, 05, 12, 13,
plus the rebuilt features (charts, changesets/simple edits, categorization with Question cards).
Screenshots in `/tmp/finquery-review/`. Browser session `review`, viewports 1440x900 and 1024x768,
both themes. Zero console messages across the whole session.

## Verdict

FinQuery already looks and feels like a real AI product: the shell, the empty state, the reasoning
panels, the Query tool step with its SQL and rows, the import preview, the Question card, the split
editor and the confirmation dialogs are all at AI Elements quality, the copy is unusually good
("Queries and charts count the legs of a split, never the transaction itself"), German data renders
correctly everywhere the app formats it (umlauts, `-1.150,00 €`, `04.09.2026, 17:32`, `DD.MM.YYYY`),
and the central invariant holds: every figure I checked came back identical to the row of an
executed SELECT that I could expand, and the empty profile and the unanswerable question both got a
no-number answer. The problems are not architectural, they are a handful of leaks in the last
centimetre between the model and the screen, and three of them will be visible on stage: the
Question card, which is the highlight of the categorization story, never applies its answers because
the model loops for over two minutes on `set_rule`; a markdown table in a chat answer opens scrolled
past its own header so the two biggest merchants are invisible and Amazon looks like the top one;
and after any reload four of six turns show a fake user bubble reading "Validation feedback: Please
return text or call a tool." Fix those three plus the `<turn|>` token that leaks into answer text and
the demo is strong; leave them and the audience will see the seams before they see the product.

## What worked well

- **The numbers invariant holds.** Every figure I checked matched an executed SELECT I could expand:
  groceries May 843,60; April 505,40 vs May 843,60 in a two-row result; merchants top-10; total 2025
  57.071,78; largest single 2.850,00; chart peak 5.521,60 and trough 4.401,88 against 12 rows. The
  SQL is shown with syntax highlighting, line numbers, copy and download, `LIMIT 200` applied, and
  the sub-agent's request quoted above it.
- **No-data and cannot-answer paths never invent a number.** An empty profile answered "The profile
  is empty. You can import a bank statement on the Import page to see your spending." with no query
  call at all (5.1 s).
- **Import is the strongest page.** Preset detected by header with encoding and delimiter shown
  (`433 rows · cp1252 · delimiter ";"`), the model proposal badged "Proposed by the fast model" and
  flipping to "Your mapping" / "Mapping edited by you." the moment I touched a select, an 8-row live
  preview that re-parses on every change, and duplicate counting that reported "Imported 0 of 433
  rows... 433 rows were already in this profile and were skipped."
- **Categorization quality.** 408 of 433 bookings auto-categorized (94 %), and the 25 uncertain rows
  arrived grouped by merchant with booking counts, the raw description, top-guess buttons and a free
  text field, in an auto-created and auto-opened "Review sparkasse-2025.csv" conversation.
- **The simple-edit card is exemplary:** "Set DÖNER HAUS Kreuzberg to Dining", an Edit badge, an
  Applied/Reverted status, a table showing `Needs review → Dining` with the old value struck
  through, and an Undo that really reverted (verified in the API).
- **Stop and continue.** Stop kept the partial turn with a "Stopped" chip next to the model chip and
  the completed tool step; the next message continued naturally in 9.6 s; the reload preserved the
  interrupted marker.
- **Memory across chats.** The `remember` tool stored the Anna rule, a brand-new conversation
  answered from it with a "1 memory used" chip, the Memory page showed it with a Rule badge and "you
  asked for it" provenance, inline edit saved on blur, and the delete dialog quoted the exact memory
  text back before forgetting it.
- **Transactions page.** Text, date-range, category, account and Needs review filters all narrow
  correctly (866 → 28 → 16 → 0 → 865) with a good empty-results state, inline edits save on
  click-away and persist umlauts, the split editor shows a live "Legs add up to … unaccounted for"
  hint and the server guard refuses a bad sum, the bulk bar shows the selected sum
  ("3 selected -19,90 €"), and both destructive dialogs are honest ("Importing the statement again
  is the only way back.").
- **Charts.** A sandboxed iframe line chart with `€` axis labels, short German month band labels, a
  shape badge, an expandable "SQL and 12 rows", data mapped from rows rather than inlined, and
  correct rendering in both themes.
- **Craft details.** Tabs keep a per-tab draft across a switch and a reload; the profile dialogs
  disable Create until you type and disable Delete when only one profile exists; keyboard focus is a
  clear green ring; the context badge popover reads "21.1% · 6.9K / 33K · Fast slot · Memories in
  prompt 0" plus "Past 60 percent, turns older than the last six are summarized."
- **Zero console messages** for the entire session, including the chart iframe.
- Ticket 19 (transactions freeze after an inline edit then Add a leg) **did not reproduce**: inline
  edit, blur-save, expand, add a leg, add a second leg, save, all stayed responsive (eval round trip
  0.2 s).

## Top five fixes before Monday

1. **Make the Question card apply its answers.** Do not let the model sequence a batch: turn the N
   answers into N deterministic `set_rule` calls in code, or force one tool call per answer. Today
   the centrepiece of the categorization demo loops for over two minutes and applies nothing.
2. **Stop the markdown table scroll box from opening scrolled.** Reset `scrollTop` when streaming
   ends (or drop the fixed max height), and add a scroll hint. Right now a chat answer hides its own
   header and its two biggest rows, which is worse than showing nothing.
3. **Filter framework retry requests out of the persisted UI messages** (ticket 18) and drop the
   empty assistant fragments they create. That removes the fake "Validation feedback" user bubbles
   and, with them, the mislabeled model chip.
4. **Strip the `<turn|>` marker in the stream splitter.** A one-line fix that removes a raw model
   token from three of the answers in the demo script.
5. **Make the answer language follow the latest user message**, and while in the prompt, tell the
   model to format money German-style (`843,60 €`). One pass fixes the German-answer-to-English-
   question problem, the German chart title and the en-US figures in prose.

Runners-up if there is time: route bulk recategorization through the changeset preview with
Apply/Discard (story 58), and either wire or hide the disabled chart thumbs.
