# 60: Type anything to answer a card

**What to build:** While a card the agent asks with is open, the user can type the answer into the composer instead of pressing a button. Question cards of every kind (category rule, duplicate decision, mapping confirmation, extraction review, transaction draft) and the changeset preview (Apply, Discard) all take typed answers. Buttons stay as the fast path. The cards lose their per-row free text fields, so there is one place to type. Grilled with the user on 2026-09-06; decisions below are settled.

**Blocked by:** 07, 09, 11, 22, 30, 33, 44 (merged)

**Status:** ready-for-agent

Decisions, settled:
- Scope: every open card, the changeset preview included ("apply", "discard", "anwenden", "verwerfen" work; Apply still writes only after the deterministic match or the model's explicit `apply` answer, never on a guess).
- Interpretation: match first, model second. A typed message while a card is open is first matched deterministically in code: an option label or value (case and accent insensitive, English and German synonyms for yes, no, skip, apply, discard, keep both, delete), or a row reference plus an option (row number, "the first two", the merchant or the label text of the row, "Rewe is groceries", "alle Lebensmittel"). A full match fills the answers and resumes the parked run with `DeferredToolResults`, no model call. Anything else is handed to the chat agent as the free-text answer of the open call (the existing `text` answer field, one per card or per row), with an instruction block that lists the open card's rows and options and says: map the message to answers where it clearly refers to them, answer the message as a normal question where it does not, and never invent an answer for a row the user did not mention. For the changeset preview the model may only return `apply` or `discard` or nothing.
- Unrelated message: the chat agent answers it and says in one line that the card is still waiting; the card stays open and answerable, both by buttons and by typing. A card is never skipped on the user's behalf.
- Partial answers: the answered rows apply (the existing appliers run per answer), the card re-renders in place with those rows marked done and the others still open, and the agent says which are left. The turn that parked on the card is rewritten as today (`replaces`), with the card's `output` carrying the answers so far.
- Composer: while a card is open in the conversation, the placeholder reads "Answer above, or type anything", and the card's single-choice options (question-level `options`, or the one row's options when the card has one row, or Apply and Discard for a changeset) show as clickable chips directly above the input, using the same suggestion chip component; a chip click sends the deterministic answer. Multi-row cards show no row chips (too many) but the placeholder still says typing works.
- Cards: the per-row free text fields and `allow_free_text` go from the card UI; the model-facing schema keeps `allow_free_text` accepted and ignored for one release so stored turns still render (note it in ask_user.py; remove in a later ticket). Buttons, the Send answers flow and the answered state stay.
- Safety: the numbers invariant is untouched; a typed answer for a mapping confirmation or an extraction review still goes through the same appliers and guards as a button; a deterministic match never applies a destructive option (delete, discard of an import) on a fuzzy match, only on an exact label or synonym.
- Tests at the HTTP seam with the scripted FunctionModel: an exact label answers with no model call (assert the model was not called); a row-plus-label answers one row and leaves the others open; "apply" applies a changeset and "discard" discards one; a German synonym works; an unrelated message gets an answer and leaves the card open; a free-text answer the model maps resumes the run with the mapped answers; a fuzzy "delete" does not delete; reload keeps a partially answered card answerable.
- Docs: ADR 0008 (ask_user) gets a consequences paragraph; `docs/explainers/09-categorization-and-question-cards.md` and the demo script (type an answer in one step); CONTEXT.md if a term is new.
