# Intelligent Agents: project task description (version of 2026-07-06)

Transcribed from `task-description.pdf`, the course's own sheet. Wording kept, formatting simplified.

The project can be done alone or as a pair and makes up 40 percent of the grade. All required
features have to be implemented; a certain number of elective features has to be chosen and
implemented. Presentations on Monday 2026-09-07. Hand-in as a ZIP archive by Monday 2026-09-14
(a download link is allowed if Moodle's limit is exceeded, available until the end of the semester).

## Required features (all of them, solo or pair)

- Runnable with `uv`, either as a self-contained script or via `uvx`.
- A user interface. Any framework that runs on Windows, macOS and Linux (graphical, for example
  marimo plus wigglestuff or NiceGUI, or textual, for example Textual). The feature requirements
  are the same for a textual interface.
- A chat interface:
  - user input by sending text messages;
  - the conversation history visible to the user;
  - the user can view any part of the prior history (scrolling or paging).
- The ability to start, stop and resume chats:
  - switching between conversations;
  - create new, continue old and remove old conversations.
- The ability to switch the underlying LLM used for generation:
  - the interface supports loading at least two different models for generation.
- A simple memory mechanism for recalling prior information from groups of chats, similar to the
  "Project Folder" feature of ChatGPT or Claude.
- At least two fine-tuned models for special purposes (full, LoRA or QLoRA). LoRA or QLoRA is
  recommended: more efficient to train and lightweight to exchange.
- A video demo of the project:
  - demonstrating the required and elective features that were implemented;
  - demonstrating at least one real-world use case that benefited from the elective features.

## Elective features (two solo, four as a pair)

- Adaptive Retrieval Augmented Generation: the diagram from the slides (judge, rewriter,
  multi-turn retrieval and summarization) or an equivalently complex approach; user-provided
  documents, at least text files and PDFs.
- Extensible tool calling where the user provides tool definitions on the fly (for example a
  JSON with name, type "shell", command and typed args) that the model can later call.
- Sub-agent deployment: a sub-agent fulfils an LLM-defined task, realized as a tool call where
  the model calls upon another LLM to do a certain task. Extra credit if the controlling LLM can
  continue without waiting for the sub-agent.
- Securely running code generated by the system and using its outputs: a safe subset of the
  Python stdlib plus common data, ML and plotting libraries; never able to change files outside
  its designated location; sandboxing, containerization, safe defaults.
- Repeated, self-controlled web search to improve generation: further than the direct results of
  DuckDuckGo or Google; the model finds and visits pages and uses the information within.
- Preference optimisation via human feedback: sometimes the user is presented with a choice of
  generated texts and picks the preferred one; code to train a LoRA or QLoRA on that choice data
  so the model can be continuously improved.
- Multimodal ingestion, especially images: most file types (pdf, images, audio, text, word,
  excel); an inherently multimodal model (Vision plus Language) is expected for generation.
- Concurrent multi-user support: more than one user, each with their own chats, projects and
  memory; independent and concurrent generation.
- Intelligent context management: at least context compression and context isolation, as well
  as context selection.
- Advanced prompt caching by implementing one method (like H2O) yourself.
- Tree-of-Thought reasoning as a user-enabled "thinking" mode.

## What FinQuery claims (pair, four electives)

Required: all of the above, with the profile as the "group of chats" the memory belongs to, the
catalog of four chat models (two local, two cloud) as the loadable models, and the query and
chart adapters as the two fine-tuned models (training in progress, tickets 43 and following).
Electives claimed, revised 2026-09-06: intelligent context management, sub-agent deployment,
multimodal ingestion (images, PDFs, text, CSV, XLSX and DOCX through the two local
vision-language models under the extraction guards; audio is out of scope), self-controlled web
search. Built and then removed on 2026-09-06: preference optimisation via human feedback (the
choice UI and the DPO scripts existed; ticket 59 removed them so the product stays simple). Built
but not claimed: sandboxed execution of generated chart code (JavaScript in an isolated frame,
not Python). Not built: adaptive RAG, user-provided tools, concurrent multi-user, prompt caching,
Tree-of-Thought.
